1. Introduction

The CBL Schedule Creator is a local web application for configuring workforce requirements, generating and reviewing weekly employee schedules, managing employees and BambooHR schedule locations, tracking attendance, and publishing accepted shifts to BambooHR.

Requirements

  • Windows
  • Python 3.9 or later
  • Google Chrome
  • Network access to the configured database (PostgreSQL deployments) and to BambooHR for integration features

2. Starting the app and signing in

Start the app

  1. Install dependencies once: open a terminal in the Schedule Creator folder and run python -m pip install -r requirements.txt.
  2. Double-click Start-Schedule-Creator.bat. It starts the server on 127.0.0.1:5001, waits for the authentication API to respond, and opens the app in Chrome.
  3. If Chrome does not open, browse to http://127.0.0.1:5001/.

Note: If the window reports that the API did not respond, read the server window for the startup error. A database connection timeout means the configured database host is unreachable. If port 5001 is already in use, close the other server first.

First-time administrator setup

  1. On first launch, from the computer running the app, create the initial administrator with a unique password of at least 14 characters.
  2. Enroll an authenticator app using the displayed setup secret and verify the current six-digit code. Multi-factor authentication is mandatory.

Signing in

At each sign-in, enter the BambooHR subdomain of the business, the administrator email, the password and the authenticator code. The same email can administer several businesses; passwords and MFA are managed separately for each business. Use Sign out in the application header when finished.

4. Scheduling workflow at a glance

  1. Configure location × role pools, shift starts and demand shares (Location roles).
  2. Set each employee's availability for every shift start (Roster settings).
  3. Set the scheduling controls and lock the configuration (Controls & lock).
  4. Generate schedules, or upload completed schedules, then review coverage, constraints and time-off warnings (Weekly schedules).
  5. Accept schedules to save them in the app database. Accepted schedules can be reviewed later, and acceptance can be undone.
  6. Preview and publish selected accepted shifts to BambooHR (Publish to BambooHR).
  7. Track clock-ins against the accepted shifts (Attendance).

5. Page guide

5.1 Overview

Shows configuration status, the latest saved schedule review, overtime and warehouse capacity planning (when your tier includes it) and model notes. Use it to see what still needs attention before generating schedules.

5.2 Location roles

Choose which location × role pools are scheduled and add or remove possible shift start times for each pool.

  • A new shift start begins with a 0% share. Allocate its share on this page.
  • The shift end is determined automatically from the shift duration set in Controls & lock.
  • After adding a start, set each employee's availability for it in Roster settings.

5.3 Roster settings

Set each employee's constraints within their location-role pool: flexibility, reason if unavailable, preferred start, proximity and random rankings (1–3), attendance score (0–100), daily availability and availability for every configured shift start.

Note: Inactive employees remain visible but are excluded from schedules.

5.4 Controls & lock

Define the generation controls: the first Monday, paid hours per shift, elapsed shift span, minimum rest and related rules. Review the Resolved controls preview, then lock the configuration. Generation advances the week by seven days and selects each enabled pool automatically.

  1. Review the configuration checks. Blocking issues must be fixed before you can lock.
  2. Lock the configuration.
  3. Select Generate schedules.

5.5 META · operating days

Define how each location works: daily operating intensity per location. Intensities are normalised across open days. A closed day receives no demand or make-up shifts; you may explicitly enter 0 for a closed day.

5.6 Weekly schedules

Lists every saved schedule, by pool and week, with demand coverage, supplemental shifts and employee target shortfalls.

Common actions

  • Generate schedules or Refresh & shuffle all: each generation uses fresh randomness. Undo last shuffle restores the previous result.
  • Accept a schedule to save it to the database. Previously accepted shifts can be viewed later; Undo accept removes only the accepted copy.
  • Click a shift to change it manually using the options configured in Settings.
  • Upload schedules · XLSX imports completed schedules; Download schedule template provides the format. Empty shift cells are OFF.
  • View time-offs or Upload time-offs · XLSX to review leave that affects scheduling.
  • Trade shifts swaps shifts between employees (requires exactly five shifts each; Silver tier and above).
  • Email schedules creates confirmation drafts for each schedule location's manager. Attach the downloaded workbook before sending. The app never sends email itself.
  • Download filtered or all schedules (XLSX) or a combined CSV.

5.7 Employees

A directory of BambooHR and manually added employees.

  • Refresh BambooHR employees imports the active roster. New records start inactive until their app location, role and roster availability are reviewed. Existing mappings are kept; employees missing from BambooHR become locally inactive. Conflicts with manual records need an explicit same-person / different-people decision.
  • Filter by location and role. Select all selects only the employees currently shown.
  • Assign a role from the row or in a batch. Changing a role deactivates the employee until the roster profile is reviewed.
  • Add manual employee creates a record with a generated MANUAL-… ID. Manual employees are never published to BambooHR and are the only employees that can be deleted.
  • Row actions: Edit, Roster settings / Complete profile, Make active / Make inactive, and Delete (manual employees only).

Note: Active/inactive status in this app is local and does not update BambooHR.

5.8 Schedule locations

Map each app location to one BambooHR schedule ID, set the confirmation manager's name and email, and assign employees. An employee can belong to only one schedule location. A schedule location with employees assigned cannot be deleted. Confirmation emails are addressed to the location's manager and include only that site's schedules.

5.9 Attendance

Tracks BambooHR clock-ins against shifts. The page syncs BambooHR time tracking and approved time off while open and rechecks every five minutes. Absences are classified automatically four hours after shift start. Clock entries count as evidence even if awaiting BambooHR approval; approved leave is excluded from absence classification and the score denominator.

Collapsible sections

BambooHR attendance sync, Attendance shift source, Unresolved BambooHR shift discrepancies (BambooHR source only), Attendance filters and Attendance rules start collapsed. Click a section title to expand or collapse it. Your choices are remembered while you stay on the page. The two tables (Attendance and Attendance scores) are always visible.

BambooHR attendance sync

Select Sync selected period to fetch time tracking and leave for the selected period (historical selections fetch up to 365 inclusive days). Polling pauses while the browser tab is hidden or closed.

Attendance shift source

  • Accepted shifts in this app (default): attendance is measured against accepted schedules saved here.
  • BambooHR shifts: the app reads BambooHR scheduled shifts for the selected period. You are asked to confirm the switch. BambooHR clock events remain the attendance evidence in both modes.

Unresolved BambooHR shift discrepancies

When BambooHR is the source, differences between BambooHR shifts and accepted app shifts are listed by date and employee. For each, an administrator can:

  • Use app shift: adds the app shift to BambooHR, then deletes the single-employee BambooHR shift it replaces.
  • Use BambooHR shift: updates the accepted app schedule to match BambooHR.

Each resolution requires confirmation and a reason (1–500 characters), is rechecked against live BambooHR data before any change, and is audited. BambooHR does not make add-then-delete transactional; if only one step succeeds, the app reports a partial result. Refresh before retrying. Shared multi-employee BambooHR shifts and shifts with a different duration, conflicting mapping or several shifts per employee-day cannot be resolved individually.

Attendance filters

Choose Single day or Month range, then optionally filter by location and role. Month ranges include all recorded shifts from the first month through the last; sync the period first if it has not been fetched.

Attendance rules

Set the lateness tolerance (minutes) and the attendance score period (30–45 days), then Save attendance rules.

Attendance table

Shows date, employee, location, role, shift start, clock-in, status, reason and actions. Click any column heading except Actions to sort; click again to reverse. ▲ means ascending and ▼ descending. Blank values always sort last.

  • Correct changes a shift's status (an auditable correction with a required reason).

Attendance scores table

Shows each active employee's attended / scheduled shifts, the Calculated score (attended ÷ scheduled), and the Effective score. All columns except Actions are sortable.

  • Set override replaces the effective score with a value from 0 to 100 and requires a reason (1–500 characters). The row shows a Manual override badge.
  • Remove override (inside the same dialog) restores the calculated score.
  • Overrides apply per employee until removed, do not change shift records, and every change is audited with the previous value, new value, reason and administrator.

5.10 Publish to BambooHR

  1. Check the BambooHR connection (Refresh server status).
  2. Under Select accepted shifts, choose shifts from accepted schedules.
  3. Select Preview BambooHR changes. Nothing is posted at this step.
  4. Select Continue to publish confirmation, then Confirm and post to BambooHR.
  5. Review Publishing results.

Note: Publishing sends changes to BambooHR. Manual employees are never published. The API key stays on the server.

5.11 Workforce Links

A list of shared workbooks, HR tools and documentation links that open in a new browser tab.

5.12 Source & backups

  • Upload updated source replaces the configuration basis with a pre-filled workbook. During import the app pauses for a mapping review: confirm the app location, role and optional schedule location for every employee. Unknown employees are added only if you choose Add manually, and they start inactive.
  • Download workspace backup and Restore backup save and restore the workspace.
  • Download configured inputs · XLSX exports the current inputs.

Note: Saved schedules retain the source settings they were generated with.

5.13 Settings

  • Business branding: business name, team name (default Schedule Management), logo (PNG/JPEG/WebP up to 2 MB), colours and the BambooHR tenant ID. Branding appears throughout the app and in the email signature.
  • BambooHR API key: Test key for saved tenant runs a read-only check. Use as app API key explicitly promotes a successfully tested key to the server.
  • Business membership & administrators: view the tier and manage administrators (see section 8).
  • Sidebar menu: show or hide pages. This is a preference, not a security boundary.
  • Schedule email: the fixed Cc to the workforce mailbox can be switched off, and additional non-working dates (one YYYY-MM-DD per line) can be added. Deadlines exclude the sending day, weekends and the listed dates (Jamaica time).
  • Workspace file: Download Portable ZIP Bundle exports configuration and saved schedules. API credentials are excluded; treat the bundle as confidential.
  • Overtime planning (Gold and above): overtime forecasting and warehouse FTE volume capacity.

6. BambooHR integration notes

  • The server reads BAMBOOHR_API_KEY from its environment configuration. Never paste the key into screenshots, chat or source files. If a key is exposed, revoke it in BambooHR and configure a replacement through the app's secured settings.
  • Time-off data is fetched when generating or refreshing schedules. If the key is missing or BambooHR cannot be reached, scheduling continues without it and the schedule is marked for review.
  • Saving a different tenant changes the tenant used by all future time-off, attendance and publishing requests.

7. Business Hub and business account

Multi-business registration, membership approval and tenant account management are available through the Business Hub (/hub). The main business administrator can view the membership at /business, change tier, and pause, resume or cancel membership. Actions take effect immediately, require confirmation and are audited. Cancellation retains data and requires the platform owner to restore access. No billing is processed by this deployment.

9. Developer change requests

The Developer change requests page records the product roadmap. First use creates a developer username and a unique password of at least 14 characters from the computer running the app. The page supports sign-in, credential updates, status filters and dependency checks. It does not launch agents or change code.

10. Troubleshooting

SymptomWhat to check
"The updated Schedule Creator API did not respond" when startingRead the server window. A ConnectionTimeout means the PostgreSQL host is unreachable: restore network access. Do not switch to SQLite for production data.
Port 5001 already in useClose the other server or process using port 5001.
BambooHR scheduled-shifts request failed with HTTP 422Refresh the attendance page and retry. The app now queries only numeric BambooHR employee IDs and sends a valid time range. If it persists, report the exact message.
Time-off data missing from a scheduleThe BambooHR key is missing or BambooHR was unreachable. Check Settings > BambooHR API key and review the schedule carefully.
Attendance discrepancy cannot be resolvedIt may be stale (refresh), shared by several employees, or have a different duration or mapping than the app supports. Adjust in BambooHR or the app manually.
A page is missing from the sidebarIt may be hidden in Settings > Sidebar menu, or the tier may not include it.

11. Running on SQLite for testing

When SCHEDULE_CREATOR_DATABASE_URL is empty the app uses SQLite at data\schedule_creator.sqlite3. This is suitable for testing, but it is a separate data set from PostgreSQL, has no row-level tenant isolation, and has no BambooHR credentials until you enter them. Do not use it for production data.

12. Security and data handling

  • Keep the data folder, flask_secret.key and mfa_encryption.key private and back them up with the database. Losing the MFA key prevents existing authenticator secrets from being decrypted.
  • Exported bundles and backups contain confidential workforce data.
  • Sign out from the header when finished.

13. Keeping this manual current

Every change to the app that affects what users see or do must update this manual in the same change:

  1. Edit user_manual_content.py (relevant section, plus a new REVISIONS entry with the date and a one-line description).
  2. Run python build_user_manual.py to regenerate docs/User-Manual.html and docs/User-Manual.docx.
  3. Run the test suite; it fails if the committed HTML is out of date.
